# 画面编码方案 — 设计稿 v0（中文版）

**在你签字之前不跑任何东西。** 这是对 Appendix B 的重做，而重做的
核心基本只有一件事：旧 prompt 向模型要了一个身份判断，模型就给了它
一个身份判断。

英文版：`docs/prompts/video-coding.md`。字段名保持英文，因为它们会
直接变成代码里的列名。

## 旧 prompt 的问题

```
VIDEO_IDENTITY_PRESENT_VISUAL：这条视频里是否存在一种
常与中国女同亚文化美学相关联的、视觉上可辨识的性别呈现风格？
```

变量名叫 *identity*（身份），定义却是一串发型，跑出来的结论是"大部分
视频都有 identity presence"。**这个结论是被问题本身制造出来的**：鲻鱼
头、短寸、"androgynous appearance"、"other masculine-coded styling"
这四项加起来覆盖了平台上大部分短发，这个测量不可能返回别的答案。

更深一层的问题就是你自己说的那句：**codebook 把女同身份定义成一组
刻板外形，然后报告说在女同内容里找到了这组外形。** 不管这测到了
什么，它测的不是那个亚文化 —— 它测的是 codebook 自己。

由此派生三个结构性毛病：

1. **把推断当成了观察。** "androgynous"、"masculine-coded" 是编码者
   的读法，不是画面里的特征。两个编码者不会一致，而且**定义写得再
   细也修不好** —— 分歧发生在类别上，不在画面上。
2. **复合项拆不开。** Type 5 是"多个特征同时出现"。一旦一条视频被
   判成 5，后面任何分析都问不出"是哪几个特征"，而唯一值得问的问题
   ——"哪些特征招来审核"—— 就此关闭。
3. **参照系是亚文化本身。** 但审核不是对着女同美学做反应的，它是对着
   **偏离平台自身常态**做反应的。拿亚文化当尺子，量的是错的那一段
   距离。

## 重构的思路

你的 digital ethnography 已经指出了该测的东西：审核反应的是**不合
常规的性别呈现** —— 男性显得女性化、女性显得非常男性化 —— 而不是
"女同身份"本身。这对这项研究反而是更好的研究对象，因为它可观察，
而且它就是审核正在反应的那个东西。

所以重构遵守三条规则：

**1. 模型永远不输出身份判断。** 它只记录特征，索引由研究者在之后
自己搭建。这是解开循环的那一刀：「头发是否剪到耳朵以上」在画面里
有答案，「她是不是 T」没有。

**2. 参照系换成平台主流，而不是亚文化。** 问题永远不是"这是不是
T 向的"，而是"**这离抖音上女性被常规呈现的样子有多远**"。那才是
审核在作用的那段距离。

**3. 视频*展示了*什么，和视频*自称是*什么，是两组不同的字段。**
屏幕上的 `#长发T` 是作者自己的陈述，作为证词进入语料；它**绝不能
参与外形变量的判断**，否则循环会从另一头重新合上。

T/P/H 没有消失 —— 它从"框架"变成了"被观察的对象之一"。

## 字段方案

严格 JSON，一条帖子一次调用，`temperature 0`，**任何时候都不传入
下架结果**。

### A. 可编码性 —— 它决定后面所有字段

```
people_visible      : int    画面中可见的人数
primary_subject     : "single" | "pair" | "group" | "none"
face_visible        : bool   是否有清晰可见的面部
coding_possible     : bool   纯文字卡、风景、只拍手等情况为 false
```

若 `coding_possible` 为 false，B 和 C 的所有字段一律为 `null`。
**无法编码的帖子记为无法编码，绝不硬塞进某个类别** —— 而且落在
这一类的比例本身，就是关于这批内容长什么样的一个发现。

### B. 可观察的外形 —— 逐人记录，不做任何解释

对主要对象编码；`primary_subject` 为 `"pair"` 时，第二个人另开一组。

```
hair_length   : "shaved"（寸头/光头） | "cropped_above_ear"（耳上短发）
              | "ear_to_jaw"（耳到下颌） | "jaw_to_shoulder"（下颌到肩）
              | "below_shoulder"（过肩） | "not_visible"
hair_mullet   : bool   专指鲻鱼头：顶与两侧短，颈后留长
hair_undercut : bool   两侧或后颈剃短/推短
hair_dyed     : bool   非自然生长的发色
makeup_visible: "none" | "light" | "heavy" | "not_visible"
nails         : "short_bare"（短而素） | "long_or_decorated"（长甲或美甲）
              | "not_visible"
upper_garment : "fitted"（修身） | "loose_or_boxy"（宽松/廓形）
              | "not_visible"
menswear_items: [ "necktie"（领带） | "suit_jacket"（西装外套）
                | "oversized_shirt"（oversize 衬衫）
                | "sports_jersey"（球衣） | "cap"（帽子）
                | "chain"（链条） | "none" ]
chest_presentation : "flattened_or_bound"（压平/束胸）
                   | "unmodified" | "not_visible"
skin_exposure : "covered"（包裹） | "arms_or_shoulders"（露臂/肩）
              | "midriff_or_legs"（露腰/腿） | "not_visible"
```

这里每一项在画面里都有答案，没有任何一项需要编码者先决定"我看到的
是什么样的人"。

### C. 神态动作 —— 记录行为，不记录形容词

旧 prompt 这一块是空白，你说它重要，是对的；陷阱在于
"masculine demeanour"就是动词形式的刻板印象。所以这里全部写成
**可描述的行为**：

```
stance_wide      : bool  站立时双脚分开超过肩宽
hands_in_pockets : bool  手插口袋
arms_crossed     : bool  抱臂
gaze_direct      : bool  直视镜头而非回避
head_tilt_or_chin_tuck : bool  "可爱"姿势：歪头、收下巴
peace_sign_or_heart    : bool  比耶 / 比心
hand_gesture_dance     : bool  手势舞：只动手和手臂，身体基本不动
full_body_dance        : bool  全身舞蹈
lip_sync               : bool  对口型
```

"男性化神态"这个索引，在分析阶段用这些行为搭建，规则写进论文、让
读者看得见。**绝不能搭在 prompt 内部** —— 那样它既不可见也不可修改。

### D. 唯一的判断项，单独隔离并标明它是判断

审核分析确实需要一个汇总变量。因为它是判断而非观察，所以它被单独
拎出来、给定锚点、并且必须报告信度。

```
presentation_distance : 1 | 2 | 3 | 4 | 5 | null
```

> 主要对象的呈现方式，离**中国主流短视频中女性被常规呈现的样子**
> 有多远？
> 1 = 常规女性化（长发、可见妆容、修身衣着、柔和造型）
> 2 = 基本常规，有一两处偏离
> 3 = 混合，或没有明确方向
> 4 = 多处男性化偏离（例如同时具备：短发 **且** 宽松男装 **且**
>     无可见妆容）
> 5 = 以主流标准看呈现为强烈男性化
> null = 可见信息不足以判断
>
> 比较对象是**平台主流**，不是女同亚文化，也不是编码者自己对性别
> 的感觉。

必须报告 κ。κ 低于 0.6，说明锚点没起作用，**改锚点，不改数据**。

### E. 关系内容 —— 可观察，且是下架预测的强候选

```
two_women_together   : bool  画面中同时出现两名女性
physical_affection   : "none"（无） | "proximity"（贴近）
                     | "hand_holding"（牵手） | "embrace"（拥抱）
                     | "kiss"（亲吻）
presented_as_couple  : bool  通过构图、情侣装、戒指、画面内文字等
                             呈现为一对
```

### F. 帖子的自述 —— 证词，永远不是推断

从屏幕文字、贴纸、以及图文的图内文字读取（**图文必须先 OCR**）。

```
onscreen_tph_terms   : [ 逐字记录：长发t、高p、姐1、攻 …… ]
onscreen_wlw_terms   : [ 逐字记录：wlw、lwl、les、拉、女同 …… ]
onscreen_relationship_terms : [ 逐字：老婆、女朋友、姐姐 …… ]
onscreen_moderation_terms   : [ 逐字：限流、被屏、无不良引导 …… ]
onscreen_contact     : bool  屏幕上出现 QQ / 微信 / Telegram 号
```

**逐字抄录，不做归一化。** 词表是从这一列长出来的，这比分类本身
更有价值。

### G. 置信度

```
confidence : 0.0-1.0
notes      : 一行；只在确实有异常的时候写
```

## 为什么这样更能回答审核问题

结果变量是"是否被下架"。旧方案只有一个复合身份标志，所以结论只能是
"身份呈现强的更容易被下架" —— 既不意外，也没有可操作性。

新方案的预测变量是可分离的，问题因此是真问题：

- 预测下架的到底是**头发**、是**衣着**，还是**两名女性之间的亲密
  动作**？
- 在控制住 `physical_affection` 之后，`presentation_distance` 是否
  仍然预测下架？**如果仍然预测，就说明平台作用的是性别呈现而不是
  同性恋本身** —— 这正是你 ethnography 的论断，现在它可检验了。
- 如果外形不预测、而屏幕上的 T/P/H 词预测，那就把**"被识别为
  queer"**和**"看起来性别不合规"**分开了 —— 这是两种不同的审核
  机制，旧 codebook 把它们糅成了一个。
- `onscreen_moderation_terms` 和账号名里的标记，提供了第二个
  由作者自述的测量，可以和观测结果相互印证。

目前约有 60 个下架事件，**预测变量上限大约是六个**，再多就是在拟合
噪声。所以回归会用一组很小的、**事先定好的**变量 —— 大概率是
`presentation_distance`、`physical_affection`、`two_women_together`、
`onscreen_tph_terms`、`hair_length`、格式（视频 / 图文）—— 其余全部
只做描述。**在看到结果之前就把这六个定下来**，是这件事诚实与否的
关键。

## 几条实务

- **图文是图片，文字在图片里。** 先 OCR，再跑同一套字段。图文的
  caption 通常只有一行，所以 F 区才是它们内容真正所在的位置 ——
  这也正是现在角色词有 85% 读作 absent 的原因。
- **只有存档副本能分析。** 一条在被下载之前就下架的帖子，永远无法
  分析。所以多模态语料天然偏向"活得够久、等到我们下载"的那些；
  要做"画面预测下架"，**必须限定在下架前就已存档的子集**，否则
  又是一次幸存者偏差。这个子集有多大，跑之前先算出来。
- **一条一次调用，对结果盲，temperature 0。** 不传下架状态、不传
  日期、不传点赞数。
- **先用 30 条校准，再铺 560 条。** 先确认字段稳定，再上规模。
- **手工编 50 条算 κ。** 特征类字段的 κ 应该很高；
  `presentation_distance` 是那个必须被报告的。

## 留给你决定的四个问题

1. **编码单位。** 按帖子，还是按画面里的每个人？情侣内容很常见，
   而且两个人的呈现往往差别很大。按人更忠实，工作量大约翻倍。
2. **D 要不要保留？** 只靠特征其实足以撑起整个分析，索引在 R 里
   搭建、读者看得见。D 是便利项，而且是唯一需要为信度做辩护的
   字段。
3. **男性怎么办。** 你的论断涵盖"男性显得女性化"，但这批语料是
   女性内容。偶尔出现的男性，用同一套量表编码，还是标记后排除？
4. **`chest_presentation`（束胸）。** 我留着它，因为束胸是真实
   存在、且确实被审核的呈现方式；但它也是这里最具侵入性的一项，
   编码的对象并没有同意被这样编码。**这是我第一个会砍掉的字段。**
